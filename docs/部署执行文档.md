# UUID Generator：Windows 部署执行文档

适用项目：本文件夹中的网站。步骤按 2026-10-15 查阅的官方资料整理；平台按钮名称可能变化。

## 0. 先了解路线

本地检查 → 上传到 GitHub → Vercel 免费练习部署 → 你购买域名 → 绑定域名 → 更新正式网址 → 验证 Google Search Console → 提交站点地图。

你已有 GitHub、Vercel、Google 账号。网站没有数据库和外部服务，不需要申请接口密钥。本文不会要求你购买其他服务。Vercel Hobby 适用于个人非商业用途，本次按个人练习使用；以后添加商业用途前，查看当时的套餐规则和价格。[Vercel 官方套餐说明](https://vercel.com/docs/plans/hobby)

文中的 `example.com`、`你的项目名.vercel.app` 都是示例，操作时替换为你自己的值，不要直接照抄示例域名。

## 1. 在电脑上运行

### 1.1 检查 Node.js

打开 Windows 的 PowerShell，输入：

```powershell
node --version
```

看到 `v22` 或更高版本即可。当前交付环境已有 v24，不需要重复安装。如果提示找不到命令，到 [Node.js 官网](https://nodejs.org/) 下载长期支持版安装；装好后重新打开 PowerShell。

### 1.2 打开项目文件夹

本项目位于桌面的 `uuid-generator` 文件夹，运行：

```powershell
Set-Location "$env:USERPROFILE\Desktop\uuid-generator"
node --test
node scripts/serve.mjs
```

第一个命令进入项目，第二个执行自动检查，第三个启动本地网站。**不需要运行 npm install。**

看到 `Local: http://localhost:3000` 后，在浏览器输入 [本地网站](http://localhost:3000)。保留 PowerShell 窗口。要停止时在该窗口按 `Ctrl+C`。

如果提示端口被占用，先关闭之前启动的本项目窗口，再重试。修改代码后，停止并重新运行上述第三个命令，再刷新网页。

### 1.3 按表检查

| 操作 | 成功表现 |
| --- | --- |
| 首次打开 | 1 个 UUID，英文页面 |
| 输入 10、100 并生成 | 分别得到 10、100 个结果 |
| 再生成 | 旧结果被替换 |
| 输入空值、0、101、-1、1.5 | 有错误提示，原结果仍在 |
| 点 Copy | 粘贴到记事本，只有一个 UUID |
| 点 Copy all | 粘贴后每行一个，行数等于生成数量 |
| 点简体中文 | 打开 `/zh/`，说明和按钮为中文 |
| 缩窄窗口/手机查看线上网站 | 页面可阅读，按钮可点击，无横向整页溢出 |

先用正常浏览器窗口测试复制；如果浏览器阻止剪贴板访问，可在地址栏旁的网站权限中检查，或按提示手动复制。不要直接双击 `dist/index.html` 作为测试方式。

## 2. 把代码保存到 GitHub

对新手，推荐 GitHub Desktop，可以少输入命令。

1. 下载并安装 [GitHub Desktop](https://desktop.github.com/)，登录你的 GitHub 账号。
2. 选 **File → Add Local Repository**，选择桌面的 `uuid-generator` 文件夹。
3. 如果提示这不是一个代码仓库，点击 **create a repository here**。保持本地路径指向现有文件夹，不要误建成 `uuid-generator/uuid-generator` 两层。保留现有 README，不勾选覆盖现有文件的初始化选项。
4. 确认变化列表中包含 `package.json`、`vercel.json`、`src`、`scripts`、`tests`、`docs` 和 README。如果已有首次提交，列表为空是正常的。
5. 如果有尚未保存的改动，在 Summary 写 `Initial UUID Generator website`，点击 **Commit to main**（按钮中的分支名称以实际为准）。
6. 点击 **Publish repository**，名称填写 `uuid-generator`；可以保留私有仓库选项，发布到你的个人账号。
7. 点击 **View on GitHub**，检查项目首页能看到 `package.json` 和 `vercel.json`，它们应当在最外层。

不要上传 `dist`、`artifacts` 或 `node_modules`；项目已有 `.gitignore` 自动忽略它们。源代码会在 Vercel 自动整理成发布文件。

## 3. 先部署到 Vercel

1. 打开 [Vercel 控制台](https://vercel.com/dashboard)。
2. 选 **Add New → Project**，从 GitHub 导入 `uuid-generator`。如果找不到仓库，给 Vercel 访问该仓库的权限。
3. Project Name 可填 `uuid-generator`；名称冲突时加你自己的短后缀。
4. 核对设置：

| 设置 | 填写内容 |
| --- | --- |
| Framework Preset | `Other` |
| Root Directory | 保持项目根目录，不要选 src 或 docs |
| Build Command | `node scripts/build.mjs` |
| Output Directory | `dist` |
| Install Command | 代码已提供，无需安装依赖；保留 `vercel.json` 中的配置 |

5. 先不填写 `SITE_URL`，点击 **Deploy**。
6. 等待显示 **Ready**。在项目的 **Domains** 中找固定的生产地址，例如 `你的项目名.vercel.app`；不要拿每次部署都会变的预览地址当正式地址。
7. 进入项目 **Settings → Environment Variables**，新增：名称 `SITE_URL`，值 `https://你的项目名.vercel.app`，适用环境选 **Production**。
8. 回到 **Deployments**，找到最新生产部署，菜单中选 **Redeploy**。环境变量修改后，必须重新部署才生效。
9. 用无痕窗口打开这个地址，检查生成、复制、中文切换，以及 `/sitemap.xml`、`/robots.txt`。此时里面的地址应该指向这个固定的 Vercel 网址。

成功标准：没登录 Vercel 的人也能打开并使用网站。如果看到登录或访问限制，检查项目 **Deployment Protection**，确保生产网站公开可访问。预览地址是否受保护与生产地址可能不同。

构建步骤和输出目录来自 [Vercel 官方构建说明](https://vercel.com/docs/builds/configure-a-build)。Vercel 可以在代码推送到 GitHub 后自动更新部署，见 [官方 GitHub 集成说明](https://vercel.com/docs/git/vercel-for-github)。

## 4. 网站成功部署后，你再购买域名

这一步涉及付款，由你自行操作。选择你愿意长期保留、容易拼写的域名即可，不需要为了练习买昂贵域名。购买前看清首年价格、续费价格和附加项目。本交付不代表任何域名可注册。

在下方记录：

```text
购买平台：
购买的域名：
到期日期：
Vercel 项目名：
当前生产地址：
```

后续默认把不带 www 的 `https://example.com` 当作正式主地址。

## 5. 把域名连接到 Vercel

### 5.1 在 Vercel 添加域名

打开项目 **Settings → Domains → Add Domain**，输入你购买的域名，例如 `example.com`。按界面提示同时添加 `www.example.com`，把 www 设置为跳转到 `example.com`，使用永久跳转选项（如果界面提供）。域名应连接到 **Production**。

### 5.2 在域名平台填写“指路记录”

DNS 可以理解为域名的指路簿：告诉浏览器这个域名应该去哪里。你只需要按 Vercel 当前显示的内容填写。

1. 回到域名购买平台，找到 **DNS / 域名解析 / 管理解析记录**。
2. 如果域名使用了其他平台的名称服务器，去那个实际管理 DNS 的平台填写；购买平台不一定就是管理解析的平台。
3. 对照 Vercel 显示的记录，复制类型、名称和值。

| 名称 | 通常表示 | 要填的值 |
| --- | --- | --- |
| `@` 或留空 | 不带 www 的域名 | 完整复制 Vercel 对主域名要求的记录 |
| `www` | 带 www 的域名 | 完整复制 Vercel 对 www 要求的记录 |
| Vercel 额外要求的验证名称 | 证明你有权使用域名 | 仅当 Vercel 提示时，照界面添加 |

**不要从旧教程抄固定 IP 地址或 CNAME 值。**不同项目的要求可能不同，以你项目当时显示的内容为准。只处理相同名称、与当前网站冲突的旧记录，不要删除邮箱或其他服务记录。TTL（生效缓存时间）保持默认即可。

4. 保存后回到 Vercel Domains，等待或点击刷新检查，直到显示 **Valid Configuration**。
5. 用无痕窗口打开 `https://example.com` 和 `https://www.example.com`。前者直接打开网站，后者应跳转到前者，浏览器不出现证书错误。

解析可能要等待，部分情况可达 48 小时。Vercel 通常会在配置正确后自动提供 HTTPS 证书，无需另买证书。[官方域名配置说明](https://vercel.com/docs/domains/working-with-domains/add-a-domain)

## 6. 把网站内部的正式网址改成你的域名

绑定域名后，还需要修改一次设置，避免站点地图仍指向临时地址。

1. Vercel 项目 → **Settings → Environment Variables**。
2. 把 Production 环境的 `SITE_URL` 改为 `https://example.com`，替换为你的真实域名。不带 www，不加 `/zh/` 等路径。
3. **Deployments → 最新生产部署 → Redeploy**，等待 Ready。
4. 打开 `https://example.com/sitemap.xml`，应当只有两个网页地址：`https://example.com/`、`https://example.com/zh/`。
5. 打开 `https://example.com/robots.txt`，最后一行应当是 `Sitemap: https://example.com/sitemap.xml`。
6. 在英文页面按 `Ctrl+U` 查看网页源代码，按 `Ctrl+F` 搜索 `canonical`。地址应是你的主域名。查看中文页面时，地址应以 `/zh/` 结尾。搜索 `hreflang`，两种语言的地址也应使用主域名。

本地文件不需要改域名。不要直接修改 `dist`，因为下一次构建会覆盖它。环境变量是 Vercel 构建时使用的一项设置。

如需在本地检查正式域名的构建结果，可运行：

```powershell
$env:SITE_URL = 'https://example.com'
node scripts/build.mjs
Remove-Item Env:SITE_URL
```

这里仍要把示例域名替换成自己的域名。最后一行恢复本地默认配置。

## 7. 验证 Google Search Console

目的是向 Google 证明你拥有这个域名。推荐选择 **域名 / Domain**，这样可包含中英文页面以及 www 等不同地址。

1. 使用你的 Google 账号打开 [Google Search Console](https://search.google.com/search-console)。
2. 选择 **添加资源 / Add property**。
3. 选择左侧 **域名 / Domain**，填写 `example.com`，只填域名，不带 `https://` 或路径。
4. 继续后，复制 Google 提供的 TXT 验证内容，通常以 `google-site-verification=` 开头。
5. 到第 5 步中实际管理 DNS 的平台，新增记录：

| 项目 | 填什么 |
| --- | --- |
| 类型 | `TXT` |
| 名称 / 主机记录 | 根域名，平台通常用 `@` 或留空表示；按平台说明填写 |
| 值 / 内容 | 粘贴 Google 提供的完整验证内容 |
| TTL | 默认 |

6. 不要覆盖 Vercel 的网站记录，也不要覆盖已有的其他 TXT 记录；新增一条即可。
7. 保存后回到 Google，点击 **验证 / Verify**。未生效时稍后重试，不需要重复新建资源。
8. 看到所有权验证成功，进入对应资源。保留 TXT 记录，不要在验证成功后删除，Google 可能会再次检查。

具体记录和值以你的验证页面为准。[Google 所有权验证官方说明](https://support.google.com/webmasters/answer/9008080?hl=zh-Hans)

## 8. 提交站点地图

1. 先在未登录的无痕窗口打开 `https://example.com/sitemap.xml`，确认不是登录页面、报错页或空文件，且两个网址均正确。
2. 在 Search Console 左上角选择刚验证的域名资源。
3. 左侧菜单点击 **站点地图 / Sitemaps**。
4. 在“添加新的站点地图”处填写完整地址 `https://example.com/sitemap.xml`。如果输入框已经带上固定网址前缀，只填写余下的 `sitemap.xml`。
5. 点击 **提交 / Submit**。
6. 看到提交记录后，保存截图或在下方记下时间。如果稍后显示 **成功 / Success**，表示 Google 已读取站点地图；“无法抓取”或解析错误需要排查，不能当作成功。

提交站点地图并不保证收录，也不保证排名。本次练习不需要反复点击“请求编入索引”。[Google 站点地图官方说明](https://support.google.com/webmasters/answer/7451001?hl=zh-Hans)

## 9. 常见问题

| 现象 | 检查办法 |
| --- | --- |
| GitHub 导入后 Vercel 构建失败 | 找日志里第一条报错；核对根目录是否能看到 package.json，命令是否为 node scripts/build.mjs，输出目录是否为 dist |
| 本地网页不更新 | 停止本地服务后重启，再刷新；源码修改后需要重新构建 |
| Vercel 的页面没有更新 | GitHub Desktop 中 Commit，再 Push origin；确认生产分支和 Production 部署成功 |
| SITE_URL 报错 | 用完整 https:// 开头的主域名，不加用户名、路径或查询内容 |
| 域名打不开但 vercel.app 能打开 | 检查域名记录是否填在真正管理 DNS 的平台；对照 Vercel Domains 的提示 |
| 域名打开后仍要求登录 | 检查生产部署的访问保护设置，使用固定生产地址 |
| 复制失败 | 在 HTTPS 或 localhost 下测试；查看权限；根据提示选中后手动复制 |
| Google 验证失败 | 检查资源里的域名拼写、TXT 内容和填写位置，等待解析生效后再验证 |
| 站点地图无法抓取 | 无痕访问完整地址；检查公开访问、域名证书、路径和 SITE_URL，重新部署后再提交 |
| 地图仍显示 vercel.app | 修改 Production 的 SITE_URL 后重新部署，不只是保存设置 |
| 搜索 Google 找不到网站 | 已验证和已提交不代表立即收录，之后再观察 Search Console |
